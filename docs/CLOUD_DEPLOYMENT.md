# Cloud deployment

The production system runs without a personal computer:

```text
Private GitHub repository
  ├─ Render Static Site → React frontend
  ├─ Render Web Service → FastAPI container
  └─ GitHub Actions → type checks, build, lint, and tests

FastAPI → Neon PostgreSQL over TLS
FastAPI → Brevo transactional mail over HTTPS
```

## 1. Database

Create a Neon PostgreSQL project in Frankfurt and copy its connection string. Adapt it for SQLAlchemy's
asyncpg dialect:

```text
postgresql+asyncpg://USER:PASSWORD@HOST/DATABASE?ssl=require
```

Change `postgresql://` to `postgresql+asyncpg://`, rename `sslmode=require` to `ssl=require`, and remove
`channel_binding=require` if Neon includes it. Keep this URL only in Render.

## 2. Backend

Push `render.yaml`, then select **New → Blueprint** in Render and connect the private repository. Render
prompts for:

```text
DATABASE_URL          Adapted Neon URL
APP_ENCRYPTION_KEYS   Fernet key generated by scripts/generate_secrets.py
ADMIN_PASSWORD        Unique password with at least 14 characters
```

Generate the Fernet key locally:

```bash
cd apps/api
python3 scripts/generate_secrets.py
```

The Blueprint configures the free Frankfurt web service, Docker build, health check, secure cookies,
generated JWT/IP secrets, and production safety checks. Confirm the backend at:

```text
https://YOUR-API.onrender.com/api/v1/health/live
```

Expected response:

```json
{"status":"ok"}
```

## 3. Frontend

Create a Render **Static Site** from the same repository:

```text
Branch:             main
Root directory:     apps/web
Build command:      npm ci && npm run build
Publish directory:  dist
```

Add build variables:

```text
VITE_API_BASE_URL=https://YOUR-API.onrender.com/api/v1
VITE_BASE_PATH=/
```

Add a rewrite so React routes work when opened directly:

```text
Source:       /*
Destination:  /index.html
Action:       Rewrite
```

## 4. Connect both services

In the API service's Render environment, set `ALLOWED_ORIGINS` to the exact static-site origin without a
trailing slash:

```text
ALLOWED_ORIGINS=https://YOUR-WEB.onrender.com
```

Save and redeploy the API. Test the public project request, contact submission, and admin login.

## 5. Enable email on Render free

Render free web services block outbound SMTP ports, including Gmail's port `587`. Use Brevo's HTTPS
transactional email API instead:

1. Create a Brevo account.
2. In Brevo, add and verify the email address that will send portfolio mail.
3. Create a Brevo API key under the SMTP & API settings.
4. Add these environment variables to the Render API service:

```text
BREVO_API_KEY=YOUR_PRIVATE_BREVO_API_KEY
MAIL_FROM=YOUR_VERIFIED_BREVO_SENDER_EMAIL_ONLY
MAIL_TO=aryantembhekar294@gmail.com
MAIL_SEND_CONFIRMATION=true
SMTP_HOST=
```

`MAIL_FROM` should normally be only the verified address, such as `name@example.com`. Use
`ADMIN_NAME` for the sender title. The API also accepts a formatted sender address for compatibility.

Save the variables and redeploy the API. Submit a new contact message and check the admin dashboard:
the message should move to `sent`. Brevo is preferred automatically when `BREVO_API_KEY` is present;
SMTP remains available for local development or a paid host.

## Secrets and operations

- Never commit `.env`, database URLs, passwords, encryption keys, or provider credentials.
- Rotate any secret shared in a message, screenshot, log, or commit.
- Free Render web services sleep after inactivity; a cold request can take about a minute.
- Contact records are committed before email is attempted, so a provider failure never loses the
  enquiry. The dashboard records `sent`, `failed`, or `not_configured` delivery state.
- Cross-site admin cookies can be blocked by strict browsers. A custom domain using `www.example.com`
  and `api.example.com` provides the cleanest production authentication setup.
